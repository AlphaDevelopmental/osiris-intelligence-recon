## How each entry was verified

* **source-verified** — every one of the 71 entries: parameter names, HTTP method and behaviour were read from the route handler (`src/app/api/**/route.ts`), not inferred from the docs.
* **LIVE ✔** — called on the public deployment with the docs' example (or a neutral) input and returned 2xx JSON.
* **LIVE ◐** — reachable and 2xx, but some documented keys were absent (an upstream data source the OSIRIS server depends on failed or the body was larger than the probe limit).
* **LIVE ✘** — the probe failed; the error is shown. This is a statement about that moment, not the route.
* **not live-probed** — deliberately not called (state-changing, paid, streaming with an id, personal data, or would make OSIRIS contact an arbitrary host).

Categories: `target-osint` (takes a target-derived subject), `global-feed`, `system`, `requires-context` (needs coordinates/ids/URLs), `stream`, `state-changing`, `ai`, `active`, `caller-specific`.  
Target contact: `none` = the target receives nothing; `indirect` = the OSIRIS server contacts the target; `active` = a scanner contacts the target.

## Rate limits (from `src/lib/ssrf-guard.ts`)

Most OSINT routes call `isRateLimited(clientIp, N)` with the **same key**, so dns, certs, whois, ip, bgp, threats, sanctions, cve, entity/expand, scanner, arcgis and ai/overview share one fixed 60-second counter per client IP per server instance; each route compares the shared count with its own threshold (20, or 30 for cve/entity/arcgis, 5 for scanner). This was observed live: after a burst of OSINT calls, `/api/scanner` answered 429. The client budgets 18 calls/min for this bucket.

## Corrections and documentation discrepancies

- **`GET /api/health`** — Docs say `status` is `operational` and list `uptime`/`endpoints`; the deployment returned `status: serving` and `uptime_seconds` on 2026-11-07.
- **`GET /api/cctv/stream-status`** — The OSIRIS server fetches the supplied URL; never fed target data.
- **`GET /api/transit`** — Docs mark both parameters optional; without either the deployment answered 400 `bbox is required` (2026-11-07). Collected with coverage=1.
- **`GET /api/arcgis`** — Docs mark all parameters optional; the deployment answered 400 `Provide ?q=keyword or ?service=URL` without them (2026-11-07).
- **`GET /api/geo`** — Reveals the operator's own location; never called automatically.
- **`GET /api/cyber-threats`** — Used for correlation: KEV vendor/product matched against technology observed on the target.
- **`GET /api/cyber-attacks`** — Used for correlation: discovered IPs matched against listed C2 addresses.
- **`GET /api/malware`** — Used for correlation: discovered IPs matched against listed C2 addresses.
- **`GET /api/osint/dns`** — Docs omit CNAME. `summary.ip_addresses` is built from the A answer set only (no AAAA) and, because answers are not filtered by type, can include CNAME targets; this client re-parses `records` by RR type instead.
- **`GET /api/osint/whois`** — Docs describe registration data only. The handler also sends a HEAD request to https://<domain> from the OSIRIS server and returns 9 selected response headers plus a heuristic `security_score`.
- **`GET /api/osint/certs`** — On crt.sh failure the handler returns HTTP 200 with `error: "crt.sh unavailable"` and no `subdomains` key; the subdomain filter uses `endsWith(domain)` without a label boundary, so this client re-filters.
- **`GET /api/osint/ip`** — `reputation.risk_level` is derived only from ip-api proxy/hosting flags.
- **`GET /api/osint/shodan`** — Docs promise banners; the handler proxies keyless InternetDB, which has no banners.
- **`GET /api/osint/portscan`** — Despite the name this is a lookup of Shodan's existing index, not a scan; no packets are sent to the target. Private/reserved targets are refused (400).
- **`GET /api/osint/bgp`** — Docs accept a prefix; the handler rejects prefixes and IPv6 (400). `prefixes` and `peers` are always empty. Previous client sent `ip=` (wrong).
- **`GET /api/osint/phone`** — Previous client sent `phone=`; the handler reads `number`.
- **`GET /api/osint/github`** — Previous client sent `username=`; the handler reads `user`.
- **`GET /api/osint/leaks`** — Personal data. Only run when the email itself is the authorised target.
- **`GET /api/osint/hudsonrock`** — Previous client sent `domain=`, which the handler rejects with 400 `Missing query parameter` — the cause of the observed Hudson Rock failure.
- **`GET /api/osint/cve`** — Docs say NVD; the handler queries MITRE's CVE API then CIRCL. Previous client sent `id=` (wrong).
- **`GET /api/osint/sanctions`** — Names are not inferred from domains; supply --org-name. /api/osint/whois already cross-checks RDAP registrant names.
- **`GET /api/osint/threats`** — Previous client sent `indicator=`, which the handler ignores — it silently returned the global pulse feed with `threat_level: UNKNOWN`. Docs mention file hashes; the handler treats every non-IPv4 value (incl. IPv6) as a domain.
- **`GET /api/osint/sweep`** — Docs: 'sweeps an address or CIDR for reachable hosts', `ip` optional, cidr example `192.0.2.0/24`. Handler: `ip` required, `cidr` must be an integer 24-32, and it only geolocates `ip` via ip-api — no host is contacted. Treated as passive; re-verify if upstream changes.
- **`GET /api/scanner`** — Docs mark `type` required; handler defaults it to `quick`. The scanner backend is not in the upstream repo. 503 = not configured; the public deployment answered 400 `Missing target parameter` to a target-less probe on 2026-11-07, i.e. a backend IS configured there.
- **`GET /api/entity/expand`** — type=ip resolves ip-api + RIPEstat prefix data. Previous client never sent `type`.
- **`POST /api/mcp`** — Handler also exports GET and DELETE.
